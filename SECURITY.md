# Security Policy

## Supported Versions

Security fixes are provided for the current `3.12.x` release line. Older
versions are not currently supported; upgrade to the latest available release
before requesting a fix.

| Version | Supported |
| ------- | --------- |
| 3.12.x  | ✅        |
| < 3.12  | ❌        |

If supported release lines change, this table will be updated.

## Reporting a Vulnerability

**Please do not report suspected vulnerabilities in public issues, discussions,
or pull requests.**

Use GitHub's private vulnerability reporting or create a draft security
advisory for this repository:

<https://github.com/cvessell-create/VessellFramework_Local_Rebuild/security/advisories/new>

If private reporting is unavailable, contact the repository owner through
GitHub and request a private channel. Do not include exploit details in a
public message.

Include, when safe to share:

- affected version, commit, component, and configuration;
- impact and realistic attack prerequisites;
- a concise reproduction case or proof of concept;
- logs or screenshots with secrets, personal data, and unrelated user data
  removed;
- any mitigation you have identified.

Do not access, modify, or retain other people's data; disrupt services; or
continue testing beyond what is necessary to establish the report.

### Response and disclosure

- We aim to acknowledge a report within **5 business days**.
- We aim to provide an initial assessment or status update within **10 business
  days** after acknowledgment, and to share further updates about every **10
  business days** while the report remains active.
- These are response goals, not guaranteed service levels. If you have not
  received a response after 10 business days, follow up privately through
  GitHub without posting vulnerability details publicly.
- If accepted, we will work with you to validate impact, develop and test a
  fix, and coordinate a release and public advisory. Please allow a reasonable
  remediation period before public disclosure; we will agree on timing with
  you where possible.
- If declined or determined not to be a security vulnerability, we will explain
  the decision and any relevant scope or evidence limitations.
- Please keep non-public details confidential until coordinated disclosure.
  We will credit reporters in an advisory only with their permission.

The project does not currently promise a bug bounty or a fixed remediation
deadline.
