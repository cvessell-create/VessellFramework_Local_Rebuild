## Before the sixth pillar

The five-pillar architecture records evidence, perspectives, constraints,
uncertainty and human release authority. The game-pattern workflow already
borrowed architecture concepts, but it did not expose a strategic model through
the specialist contract or return conditional game calculations in reports.
It was therefore possible to discuss incentives without declaring utilities,
information structure or the actor who chooses each branch.

## Blind spots and implemented response

| Blind spot | Response | Verification boundary |
|---|---|---|
| Inferring motive from narrative or outcome | Explicit declared players/actions/utilities and evidence IDs | No code can establish motives from supplied utilities |
| Simultaneous and sequential choice conflated | Separate matrix and deterministic perfect-information tree kernels | Chicken mixed and sequential fixtures must differ |
| Equal stats mistaken for measured merit | Source-bound coalition weights and quota; exact swing/pivotal fractions | User-supplied model, not empirical skill measurement |
| Reserve mistaken for realized reward | Exact base reserve with separate payout-scope warning | Sum reserve C, not sum bonus-adjusted XP |
| Reverse calculation mistaken for unique inverse | Preserve inputs and forward dependencies | No coefficient fitting or unique inverse claimed |
| Sustainable analogy mistaken for generated income | Conserved savings receipt, replenishment budget and target | Quarter/half parameters remain design choices |
| Fixture success mistaken for deployed behavior | Separate source tests from hosted movement observation | Hosted timing bug remains a game deployment issue |
| Historical blueprint mistaken for installed functionality | Preserve original catalog and missing/null statuses | No Euler/MST/SAT/matching feature claim without code/tests |
| Solver output bypassing human oversight | Existing source/preview-bound Knowing Field completion retained | Model never raises confidence or grants release/execution |
| Generated sixth-pillar record treated as presencing | Explicit source, participant gaps, dissent and limitations | Human experience remains outside machine certification |

## Full-circle cross-pillar application

PARADOX tests whether competing statements concern the same game, time and
information set. BOTTLENECK separates feasibility from willingness and includes
coordination and incentive constraints. DUAL LAYER separates reported
preferences/bids from behavior and prevents intent attribution. XFACTOR varies
payoffs, thresholds, missing actors and unexpected terminal conditions.
KNOWING FIELD records the analyst's model choices, affected people, consent,
missing voices and dissent. GAME THEORY computes conditional strategic
consequences and returns them for review, not autonomous action.

The observer participates by choosing boundaries, utility units, veto holders
and policy constants. Affected parties include game players and future analysis
subjects; no new interviews or consent-based participant study occurred.
No group consensus, human dialogue or fourth-person experience is fabricated.
Alternatives include provenance-only analysis, leaving utilities unspecified,
dynamic rather than frozen reserves, and direct contribution measures.

## Implementation and hold points

The Python kernel is independently written from equations and source records;
GPL game implementation code is not transplanted into this Apache framework.
Case intake, specialist API/client, JSON/Markdown reporting, agent instruction
loading and source packaging share the sixth-pillar contract.
Absent models are explicit NOT_SUPPLIED; malformed supplied models fail.

The kernel supports bounded normal-form matrices, deterministic trees, exact
weighted coalitions and the supplied savings transition. Chance nodes,
imperfect-information games, full mixed-equilibrium enumeration, fair-division
engines and statistical utility calibration remain out of scope here.
Existing Hail implementations are separate evidence, not magically installed
framework capabilities.

Promotion requires measurable comparative improvement on declared tasks,
held-out cases, independent review and harm monitoring. This release is a
tested reference implementation plus owner-authorized research adaptation.
Historical Knowing Field records, author paper, previous owner account and
already released reports are not retroactively rewritten.
