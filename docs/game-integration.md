# Hail to the Analyst integration (3.9.1)

> **Legacy / separate project:** This is a game integration, not part of the proposed organizational-psychology research direction.

Framework-side integration, not a completed game release. The game
feature build and server are paused at the operator's request. Components are
reused by the [architecture adaptation skill](../GAME_DEVELOPMENT_SKILL.md)
and generic analyst workflow; resume game development separately.

The rebuild connects to the user's
[hail-to-the-analyst repository](https://github.com/cvessell-create/hail-to-the-analyst)
without replacing either repository or changing their remotes. The game remains
a separate project. Install the rebuild and clone the game alongside it:

```sh
python -m pip install -e .
python -m vessell.game_bridge --game-dir ../hail-to-the-analyst \
  --output-dir /absolute/path/to/private-local-game-receipts --port 8765
```

The bridge requires the paused game's simulation and browser assets, which
are not included in this framework release or the original game commit. An
original-only game checkout cannot run these integration commands. The generic
analyst workflow does not require the game checkout.

With those assets available, open `http://127.0.0.1:8765/lab.html`. Three
requested roles are implemented in the preserved local integration:

- **Autonomous player:** a seeded JavaScript controller drives the original FPS
  through its actual fixed-step engine. Python can run and summarize its paired
  comparison via Node. Scripted policy is not described as a live LLM player.
- **Analyst coach:** the sequel's live verdicts come from Python intake,
  corroboration and consequential-use gates. Browser text explains those
  returned states; it does not calculate a replacement provenance policy.
- **Provenance mechanics and new game:** *Signal Recall* is an experimental
  information-tactics sequel with human play and autoplay, two copied source
  terminals, an independent source and four real local correction consumers.

Generate a fresh reproducible comparison (Node.js 24+ required):

```sh
python -m vessell.game_bridge --game-dir ../hail-to-the-analyst \
  --output-dir /absolute/path/to/new-game-comparison --simulate
```

It runs five paired FPS seeds and a fixed provenance-action sequence in both
framework and deliberately flawed baseline modes. Reports are synchronized,
source hashes are recorded and existing output is never overwritten.

Measured initial FPS means: baseline 41.100 simulated seconds and 6,100 intel;
planned 39.653 seconds and 6,390 intel. Both won 5/5 and hit 100% under exact
LOS observations. Planned play was not faster on every seed. These results
motivated claim-verification mechanics instead of claiming that score or
shooting demonstrates analytical ability.

The actual Python mission blocks both unsupported uses, permits the corroborated
use, writes/reads back four correction files and leaves zero stale consumers.
The comparator deliberately bypasses gameplay gating and correction and leaves
four stale files. Synthetic source roots are prescribed game inputs; no source
authenticity or real-world efficacy is inferred.

## Local-only boundary

The server binds only `127.0.0.1`, validates the Host and Origin, requires JSON,
caps request bodies and session counts, and serves only named public game assets.
It exposes no subprocess execution, scanner, remediation, credential or arbitrary
file-write endpoint. Output paths are generated by the backend, never supplied
by the browser. Do not expose this development server publicly or proxy it.
Sessions are process-local; saved claim/event reports and receipts are not a
crash-resumable controller. Game operations use real framework APIs but affect
only fictional claims and local JSON consumer files.

Static GitHub Pages cannot run Python. FPS playback remains available there;
Signal Recall must use this local bridge and fails explicitly when absent.
The VS Code task `Hail: local framework bridge` prompts for both local paths.

Regressions cover shared-root discounting, completed-session rejection,
corrupt consumer rejection, baseline behavior and actual HTTP/browser request
contracts. Game tests separately cover seed replay, resets, invalid actions
and legitimate completion of both missions. Prospective learning studies,
pixel-only perception, larger campaigns and independent evaluators remain
future work.
