# VesselFramework Skill Creator
## Version 0.1 — Research Candidate

## Status
RESEARCH CANDIDATE / NOT YET PROMOTED.
Creation of this file does not establish runtime installation or synchronization.

## Purpose
Create a skill only when a recurring decision problem needs a reusable procedure
more specific than the Master Framework and not already handled by an existing skill.

`DECISION NEED -> INTELLIGENCE REQUIREMENT -> RESEARCH -> MOSAIC ->
SKILL DESIGN -> ADVERSARIAL TEST -> PILOT -> PROMOTION DECISION`

A generated skill is not doctrine merely because it exists.

## Governing Order
1. Operator Protection / Harm Gate
2. Evidence Assurance / Provenance Firewall
3. Canonical VesselFramework doctrine
4. Forensic Framework Auditor / Adaptive Hardening
5. Skill Creator
6. Candidate domain skill
7. Executable implementation
8. Calibration / patch records

## Knowing Field integration requirement

Use [the fifth-pillar skill](VesselFramework_Knowing_Field_SKILL_v0.1.md)
when revising framework methods. Describe the observer's participation,
affected parties, missing/declined perspectives, dissent, attention, intention,
agency, alternatives and evaluation plan. Preserve embodied human knowing
as distinct from software record validation.
Mandatory human completion before new report release is an owner-authorized
policy, not empirical skill promotion. Do not relabel a generated skill or
complete schema as validated fourth-person experience.

## Scientific grounding and evidence promotion

Use [Scientific Evidence](VesselFramework_Scientific_Evidence_SKILL_v0.1.md)
and the [source/model/test crosswalk](docs/pillar-scientific-foundations.md)
for all six pillars. Reuse this shared method rather than duplicating it.
Apply the [Game Theory theory](Game_Theory_Theory_SKILL_v0.1.md),
[audit](docs/game-theory-framework-audit.md) and
[combined sixth-pillar skill](VesselFramework_Game_Theory_SKILL_v0.1.md)
for strategic models. Preserve original owner source and the
[civilian authorship caveat](docs/civilian-authorship-and-model-interference.md).
For any proposed scientific extension, record primary-source access level,
original scope, variables/units, assumptions, identifiability, alternatives,
disconfirmers and a prospective baseline/held-out evaluation.
Metadata-only sources remain bibliographic candidates.

Promotion must separate byte integrity, prior-existence anchoring, key
authorization, reproducibility, conditional mathematical proof and empirical
effects. Neither a digest, token reward, software test nor a complete human
inquiry supplies missing causal evidence or validates the whole theory.
Publish null/adverse findings and uncertainty; preserve historical sources.
New payment/receipt skills must also preserve human release, privacy and
explicit financial/execution decisions under the
[prospective roadmap](docs/blockchain-agent-economy-roadmap.md).

## Intelligence-Process Spine

### 1. Planning and Direction
Define:
- decision/task the skill must improve;
- intended user and domain;
- recurring capability gap;
- acceptable decision-usable output;
- consequence of error;
- existing skills that may already solve it;
- collection requirements and stop conditions.

**Need Gate:** Do not create a skill for a one-time answer, formatting preference,
duplicate procedure, or problem already solved cleanly by the Master Framework.

### 2. Collection
Collect candidate methods from:
1. authoritative standards/doctrine;
2. peer-reviewed or established scholarship;
3. established professional practice;
4. validated internal VesselFramework components;
5. clearly bounded experimental methods.

For each source record source/version, original scope, assumptions, limitations,
validation status, provenance, and candidate contribution.

Repeated descriptions of one parent method do not constitute independent support.

### 3. Processing
Normalize each method as:

`INPUT -> TRANSFORMATION -> OUTPUT -> ASSUMPTIONS -> FAILURE MODES ->
EVIDENCE REQUIREMENTS -> DECISION USE`

Tag claims:
SOURCE-ESTABLISHED / FRAMEWORK SYNTHESIS / WORKING HYPOTHESIS / ILLUSTRATIVE.

### 4. Analysis and Production
Run the Analytical Mosaic. Determine what methods are necessary, complementary,
redundant, conflicting, falsifiable, and decision-relevant.

### 5. Dissemination
Render a self-contained SKILL.md with triggers, non-triggers, inputs, sequence,
outputs, evidence/confidence rules, failure conditions, Harm Gate, tests,
calibration state, and version state.

### 6. Evaluation and Feedback
`PILOT -> OBSERVE -> SCORE -> DIAGNOSE -> REPAIR -> REGRESSION TEST ->
PROMOTE / HOLD / MERGE / RETIRE`

A successful-looking output is not validation.

## Analytical Mosaic

"Mosaic" means a controlled portfolio of processes selected for diagnostic
contribution. It is VesselFramework synthesis, not a claim that mosaic theory is
an uncontested intelligence doctrine.

Search relevant families:

1. Intelligence requirements/cycle — planning, collection, processing,
   analysis/production, dissemination, feedback.
2. Structured analytic techniques — key assumptions, competing hypotheses,
   indicators/warnings, challenge analysis, what-if, alternative futures,
   diagnostic evidence.
3. Systems/constraints — dependency mapping, bottlenecks, CANNOT/WILL NOT,
   opportunity/willingness, failure modes, feedback loops.
4. Cyber/risk — threat modeling, attack surface, trust boundaries, control
   assurance, adversarial paths, least privilege, observability.
5. Verification/provenance — source evaluation, lineage, independence,
   chronology, claim-evidence mapping, disconfirmation.
6. Foresight — scenarios, triggers, signposts, alternative futures,
   prospective calibration.
7. Decision/consequence — decision provenance, authority, reversibility,
   consequence, low-regret options, Harm Gate.
8. Learning/competency — Task-Knowledge-Skill decomposition, observable
   performance, competency clustering, practice/test design, feedback.

### Selection Test
Assess each candidate process for:
- relevance;
- diagnosticity;
- non-redundancy;
- evidence discipline;
- operationality;
- transferability;
- proportional analytical cost;
- visible failure signals.

Do not select a method merely because it is prestigious or familiar.

### Mosaic Handoff
For every selected method define:

`METHOD -> ROLE -> PRECONDITION -> HANDOFF -> OUTPUT -> FAILURE SIGNAL`

If two methods produce the same information from the same evidence, merge/remove
one unless the second is an intentional independent challenge process.

### Method Conflict
When methods disagree, do not average mechanically. Locate whether disagreement
comes from evidence, assumptions, horizon, scope, model structure, or decision
criteria. Seek discriminating evidence and preserve material unresolved conflict.

## Constitutional Checks
- Conclusion authority may not exceed evidence assurance.
- Missing lineage is not independence.
- Material analysis requires alternatives unless task is purely mechanical.
- Identify binding constraints where system performance matters.
- Distinguish formal/configured state from operational state when relevant.
- XFACTOR must be bounded and potentially testable.
- Consequential outputs require Harm Gate review.
- Translate findings into target-domain language; do not leak internal taxonomy
  into external deliverables without operator authorization.

## Skill Construction Contract
Candidate skill fields:
NAME; VERSION; STATUS; PURPOSE; TRIGGERS; NON-TRIGGERS; AUTHORITY/DEPENDENCIES;
INPUT CONTRACT; SOURCE REQUIREMENTS; ANALYTICAL SEQUENCE; METHOD MOSAIC;
DECISION RULES; OUTPUT CONTRACT; CONFIDENCE/UNCERTAINTY; FAILURE/STOP CONDITIONS;
HARM GATE; TEST CASES; CALIBRATION PLAN; CHANGE LOG; RUNTIME STATE.

Triggers describe decision needs, not keywords. Outputs must be observable,
decision-usable, and testable.

## Task-Knowledge-Skill Decomposition
For cyber-oriented skills define:
- Task: observable work performed.
- Knowledge: concepts required.
- Skill: observable action capability.

Do not promote a skill containing only knowledge retrieval and no observable
analytical performance.

## Research Alignment
For every imported method state:
- source/discipline;
- what is adopted;
- what is modified;
- what remains VesselFramework synthesis;
- what evidence would show the adaptation is harmful/unnecessary.

External research grounds a process; it does not automatically become doctrine.
External-standard changes trigger dependent-skill review.

## Adversarial Test Suite
T1 Normal case — intended decision support.
T2 Sparse evidence — stops/downgrades rather than invents.
T3 Conflicting evidence — surfaces conflict and discriminators.
T4 Derivative sources — avoids false corroboration.
T5 Wrong focal hypothesis — alternative can win.
T6 Declared/operational mismatch — distinguishes presence from effectiveness.
T7 High consequence — Harm Gate constrains action.
T8 Irrelevant-method pressure — refuses mosaic components adding no value.
T9 Domain transfer — works on a second case without becoming vague.
T10 Skill collision — existing skill is preferred when it already does the job.

## Promotion Gates
`IDEA -> RESEARCH CANDIDATE -> DRAFT -> PILOT -> REGRESSION-PASS ->
CALIBRATION-PENDING -> PROMOTED`

Alternative exits: MERGE / HOLD / REJECT / RETIRE.

Promotion requires a distinct recurring problem, bounded triggers, research
provenance, non-redundant mosaic, evidence ceiling, alternatives, observable
output, stop conditions, tests, doctrine conformance, and truthful runtime state.

## Anti-Bloat Rule
Prefer `MASTER DOCTRINE + SMALL DOMAIN ADAPTER` over duplicated doctrine.

Merge/retire when a parent skill subsumes the contribution, friction exceeds
diagnostic value, calibration shows no improvement, or external assumptions go stale.

## Skill Creation Record
Record:
Candidate name; date/version; operator decision need; existing-skill gap;
intelligence requirements; sources; provenance; methods considered; selected;
rejected and why; mosaic architecture; framework synthesis; assumptions; failure
modes; Harm Gate; tests/results; calibration; promotion recommendation; runtime
state; next review.

## Output Modes

### Rapid Creator
Decision need; existing-skill gap; 5–10 candidate processes; selected mosaic;
candidate skeleton; top failure modes; tests; promotion recommendation.

### Full Creator
Intelligence requirement; collection plan; research/source map; provenance map;
method comparison; selected mosaic/handoffs; complete SKILL.md; adversarial tests;
doctrine-conformance check; calibration plan; promotion state; runtime state.

## Research Basis / Attribution Boundary
May draw from intelligence-cycle models; IC analytic standards; Heuer and
Heuer/Pherson structured analysis; systems/constraint literature; OSINT and
verification practice; strategic foresight; and NIST NICE Task-Knowledge-Skill
and competency decomposition. Preserve external attribution and distinguish it
from VesselFramework synthesis.

## Final Rule
A skill is not valuable because it contains many methods. It is valuable when a
small, traceable set of methods converts a recurring decision problem into a more
reliable, testable, evidence-bounded analytical capability.
