and [Knowing Field](VesselFramework_Knowing_Field_SKILL_v0.1.md).

## Purpose, precedence and scope

Ask: **Which outcomes follow from declared actor choices, information,
constraints, transitions and utilities, and which assumptions change them?**
This supplements PARADOX, BOTTLENECK, DUAL LAYER, XFACTOR and KNOWING FIELD.
It cannot infer political allegiance, planted code, hidden intent, intelligence
or real-world fairness from a payoff table.

Use for bounded strategic inquiry, incentive/threshold sensitivity, game
mechanic review and model-based comparison. Non-strategic cases may state
NOT_SUPPLIED. Do not invent a game merely to fill the sixth section.
No additional mandatory human gate replaces or bypasses the fifth-pillar
completion. Both source and preview binding still protect every new release.

## Machine and analyst contracts

Use the [model schema](schemas/game-theory.schema.json) and
[reference kernel](vessell/game_theory.py). Require kind, boundary, players,
evidence IDs, assumptions, limitations, utility units and complete model inputs.
The executable layer checks source references and mathematical shape; it does
not verify source truth. Case CLI and specialist intake return the same
conditional result. Model size is 32 KiB; matrices have two players and at most
eight actions each; coalitions have at most 12 players; trees have depth 16,
512 nodes and at most eight choices per node. Exact fractions serialize as
numerator/denominator strings. No missing coefficient defaults to zero.

## Full-circle sequence

`OWNER SOURCE -> THEORY SKILL -> BLIND-SPOT AUDIT -> COMBINED SKILL
-> DECLARED MODEL -> BOUNDED EXECUTION -> PROVENANCE/REPORT
-> HUMAN FIELD COMPLETION -> RELEASE DECISION -> EVALUATION -> VERSIONED REVISION`

For each model:
1. State question, observer participation and affected parties.
2. Bind source IDs and separate source claims, synthesis and illustration.
3. Declare actors, actions, information, terminal conditions and utility units.
4. Test feasibility, contradictions, alternatives, excluded actors and dissent.
5. Compute the selected bounded model; retain inputs, assumptions and outputs.
6. Trace weights/decisions backward through their recorded dependencies.
7. State uncertainty, non-identifiability, harm and authority constraints.
8. Compare observed outcomes only when independently collected; revise
   coefficients explicitly with rationale and validation, never by hidden fitting.

| Pillar | Sixth-pillar handoff |
|---|---|
| PARADOX | Same context/game/information before claiming contradiction |
| BOTTLENECK | Resource feasibility, strategic incentives and coordination |
| DUAL LAYER | Reported bid versus actual behavior; no inferred hidden intent |
| XFACTOR | Sensitivity to payoffs, quotas, survival and unmodeled actors |
| KNOWING FIELD | Human observer/model choices, absent perspectives, dissent |
| GAME THEORY | Conditional consequences, assumptions and alternative models |

## Author design boundaries

Retain the locked reserve `C(B+phi)/2`, not a claim of observed contribution.
Retain survival/critical bonuses as payout adjustments, not reserve changes.
Retain quarter-deposit savings, half-reserve target and deposited harvest
budget; available XP is bookkeeping, not extra progression XP or money.
Game inventory upgrades are a separate authorized design, not an automatic
conversion of framework model output into purchases or external execution.

All historical branch claims remain dated snapshots. Recovered Euler/MST/SAT,
matching, critical-path, EDA and social-choice candidates stay candidates
unless a specific implementation and tests are added. Their established names
do not create numeric utility adapters.

## Acceptance and stop conditions

Reject unknown evidence, absent numerical payoffs, invalid quotas, duplicate
actors/actions, out-of-bounds models and inconsistent savings balances.
Tests must cover exact Chicken probabilities/expected payoffs, different
sequential information, coalition symmetry/dummy/veto, reserve normalization,
savings conservation/reverse receipts and invalid API inputs.

Do not claim exhaustive equilibrium solving, Internet-ready deployment,
ecological sustainability, novelty, real-world contribution prediction or
empirical framework improvement. Comparative evaluation is prospective.
Generated records remain previews. Completed inquiry does not confer truth,
report release does not confer action authority, and hashing earns no credits.
