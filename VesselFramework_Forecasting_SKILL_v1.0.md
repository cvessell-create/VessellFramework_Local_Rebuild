# VesselFramework Forecaster — Prospective Forecasting Skill v1.1

## Status

Current application also follows
[KNOWING FIELD](VesselFramework_Knowing_Field_SKILL_v0.1.md), the fifth pillar.
Include observer position, absent/declined perspectives, dissent and proposed
source conditions in framing. Human inquiry completion is required before
report release, but never raises forecast probability, validates prediction,
substitutes for a frozen calibration record or grants execution authority.
Historical references to four pillars below are superseded for current use.

**Skill status:** NEW / PROSPECTIVE / NOT YET EMPIRICALLY VALIDATED  
**Authority:** Operational skill; subordinate to canonical VesselFramework doctrine.

**Integration status:** Integrated with the main framework's Evidence Assurance,
Decision Provenance Chain, Four Pillars, Harm Gate, Forward-Posture ladder,
Forensic Auditor, and Calibration Log. The skill does not override those layers.

## Purpose

Convert a current-state analytical assessment into explicit, falsifiable,
time-bounded forecasts with indicators, disconfirmers, probabilities/confidence,
decision posture, Harm Gate controls, and prospective calibration.

This skill does not claim clairvoyance, deterministic prediction, or validated
forecasting superiority. Performance must be established prospectively.

## Forecasting Intake Adapter (Canonical Form)

Use one canonical intake format for all prospective forecasts in this package:

- focused situational question;
- timestamp and timezone of the forecasting decision;
- decision horizon and explicit resolution window;
- source set and provenance status;
- principal alternative and disconfirmers;
- indicators, observability path, and scoring rule.

Do not use symbolic or divinatory inputs as evidentiary sources. Forecast
objects must be built from ordinary-world evidence, provenance checks,
alternatives testing, and explicit resolution criteria. Legal, medical,
financial, safety, employment, and reputational decisions remain subject to the
ordinary Evidence Assurance, Harm Gate, Forward Posture, and Startle Gate rules.

## Core Forecasting Principle

Current-state claims require Search Gate search records and opened primary confirmation (`VesselFramework_Search_Gate_SKILL_v0.1.md`).

A forecast is not "what story seems most plausible."

A forecast is: given current evidence, constraints, alternatives, and assumptions,
what future state is being assessed; within what time window; at what probability
or confidence; what observable indicators should precede it; and what evidence
would reduce or falsify the assessment?

`CURRENT STATE → CONDITIONS → CONSTRAINTS → ALTERNATIVES → TRIGGERS →
INDICATORS → FORECAST → HARM GATE → POSTURE → OBSERVATION → SCORE → FEEDBACK`

## Required Forecasting Sequence

### 1. State the decision question
Define exactly what is being forecast and why it matters. Replace vague questions
with observable outcomes and explicit windows.

### 2. Establish current state
Tag material claims as SOURCE-ESTABLISHED, FRAMEWORK SYNTHESIS, WORKING
HYPOTHESIS, or ILLUSTRATIVE. Separate present observations from future inference.

### 3. Trace provenance and independence
Identify the origin of each major evidence stream. Repeated reporting from one
lineage counts as one stream until meaningful independence is demonstrated.

### 4. Define competing future states
Construct at least a focal forecast and a principal alternative when appropriate.
Use mutually exclusive/exhaustive alternatives where practical, but do not create
false symmetry just to fill a template.

### 5. Run discriminating VesselFramework pillars

**PARADOX:** What current claim does not fit observable preparation or behavior?
Is the contradiction a leading indicator or merely a category error?

**BOTTLENECK:** What currently prevents the focal outcome? CANNOT or WILL NOT?
What observable change would remove the constraint? Constitutive or instrumental?

**DUAL LAYER:** What does the public/declaratory layer signal? What does the
operational layer show? Which should move first if the focal outcome is approaching?

**XFACTOR:** What event, capability, third-party action, or trigger would make the
forecast obsolete? What is the earliest observable signal?

Run the Primary Brute-Force Stealth Maskirovka check first (developed by
Christopher R. Vessell), then apply reference checks (Budgetary / Structural /
Operational) only if their independent trigger conditions are met. Never use a
deception label as a substitute for evidence.

### 6. Build the condition architecture

**Necessary conditions** — without these, the outcome cannot occur as defined.  
**Enabling conditions** — increase feasibility/probability but are not mandatory.  
**Blocking conditions** — constrain or prevent the outcome.  
**Triggers** — can convert latent capability/willingness into action.  
**Dependencies** — external systems or actors whose state materially changes the path.

### 7. Build Indicators & Warnings

For each indicator specify:

**Indicator:** observable change expected  
**Direction:** raises or lowers focal probability  
**Lead time:** hours / days / weeks / months  
**Observability:** high / medium / low and why  
**Source path:** where evidence should appear  
**Specificity:** whether it discriminates focal forecast from alternatives  
**False-positive risk:** what else could create the signal

Prefer indicators that are observable and diagnostically discriminating.

### 8. Build disconfirmers

A forecast is incomplete without evidence that can move probability downward:
expected indicators fail to appear despite adequate observability; a blocking
constraint strengthens; an alternative gains independent support; the trigger
resolves; operational posture reverses; or a key assumption is invalidated.

**Absence rule:** non-observation counts only when the signal was reasonably
expected to be observable.

### 9. Assign probability and analytical confidence

1. Probability describes the event forecast.
2. Analytical confidence describes strength of evidence/model support.
3. A 70% event forecast can still have LOW analytical confidence.
4. Avoid false precision.
5. Never derive probability mechanically from source counts or pillar counts.
6. If numerical probability is not defensible, use calibrated ordinal language.

### 10. Run the Harm Gate

Add the Forecast Action Test:

- Cost of acting on a false positive?
- Cost of failing to act on a true positive?
- Which preparations are reversible?
- Which actions create escalation, legal, financial, security, academic, or
  reputational exposure?
- Is there a low-regret action useful across multiple scenarios?

**Rule:** probability determines plausibility; consequence and reversibility
determine how early preparation may be justified.

### 11. Choose posture

Use the canonical ladder:

`OBSERVE → VERIFY → CONTAIN → RECOVER → RESTRICT → ESCALATE`

Forecasts ordinarily support OBSERVE, VERIFY, or reversible preparation unless
evidence, consequence, authority, and Harm Gate conditions justify movement rightward.

Do not convert high consequence into high probability.

### 12. Freeze the forecast

Before the outcome is known:
1. Assign Forecast/Calibration ID.
2. Record timestamp.
3. Record probability/confidence.
4. Record resolution criteria.
5. Record indicators/disconfirmers.
6. Record assumptions and source lineages.
7. Record next review date.
8. Mark **FROZEN FOR CALIBRATION**.

Updates must preserve the original forecast and create a revision. Never silently
overwrite a previous probability.

## Forecast Update Protocol

`OLD FORECAST → NEW EVIDENCE → PROVENANCE CHECK → DIAGNOSTIC VALUE →
ASSUMPTION IMPACT → PROBABILITY UPDATE → HARM GATE CHECK → NEW REVISION`

Record previous probability, new probability, evidence causing change, why it is
diagnostic, alternative explanation, assumption changed, whether posture changed,
and confirmation that the original forecast remains preserved.

### Forecast State Machine

Use one state at a time and record the transition cause:

`DRAFT -> QUALITY-CHECKED -> FROZEN -> ACTIVE -> RESOLVED`

Permitted exception paths:

- `DRAFT → WITHDRAWN` when the question cannot be made observable or ethical.
- `QUALITY-CHECKED → NOT CALIBRATION-READY` when a required field or source check fails.
- `ACTIVE → EXPIRED` when the resolution window closes without a resolvable outcome.
- `ACTIVE → WITHDRAWN` only when the outcome definition becomes invalid for a documented external reason; do not use withdrawal to erase a miss.
- `ACTIVE → REVISED` when new evidence changes the forecast. Preserve the prior frozen version.

Every transition must include a timestamp, actor, evidence or reason, and the
next review or resolution date.

### Cross-Skill Handoff Rules

- **Analyst skill:** supplies the current-state assessment, source statuses,
  Decision Provenance, Four Pillars, and confidence basis. The forecaster must
  not treat an analytical conclusion as a forecast until it has a horizon and
  resolution rule.
- **Theater or domain briefer:** supplies collection context, actor timelines,
  operational indicators, and reporting gaps. The forecaster converts these into
  discriminating indicators rather than copying narrative volume.
- **Applied analytics / methods:** supports baseline construction, measurement
  design, uncertainty, scoring, and aggregation. It does not authorize causal
  claims or replace source provenance.
- **Professional marketing or public communication:** translates a resolved or
  appropriately caveated forecast for an audience. It must not remove the
  probability, horizon, uncertainty, or source-status limits needed for honesty.
- **Forensic Auditor:** audits outcome definitions, revision history, hindsight
  contamination, indicator quality, and whether a miss is being hidden by a
  changed question or extended window.
- **Harm Gate / Forward Posture:** controls what action is justified by the
  forecast. A high probability does not by itself authorize a restrictive or
  irreversible action.

### Minimum Forecast Dataset

For each calibration-grade forecast, retain the original record, every revision,
the evidence used for each revision, the final resolution evidence, and the
diagnostic category. A forecast that exists only in a final narrative cannot be
reliably calibrated.

## Resolution and Scoring

Resolve only against the predeclared outcome definition and time window.

For binary forecasts, with probability `p` and outcome `o` where occurrence = 1
and non-occurrence = 0:

`Brier Score = (p - o)^2`

Lower is better. Never evaluate the forecasting system from one Brier score.
Aggregate across prospective forecasts and inspect calibration, resolution, domain,
horizon, and error type.

If HIGH/MODERATE/LOW labels are used, track empirical outcome frequencies by label.
Do not retrospectively redefine labels.

### Diagnostic categories

- SOURCE FAILURE
- PROVENANCE FAILURE
- ASSUMPTION FAILURE
- BOTTLENECK FAILURE
- TRIGGER FAILURE
- INDICATOR FAILURE
- XFACTOR MISS
- TIMING FAILURE
- OUTCOME-DEFINITION FAILURE
- DECISION FAILURE
- NO MATERIAL FAILURE

A HIT does not automatically validate doctrine. A MISS does not automatically
invalidate it.

## Calibration Dashboard

After a meaningful sample exists, evaluate:
- calibration/reliability;
- Brier score for resolvable binary forecasts;
- resolution/sharpness;
- domain performance;
- horizon performance;
- repeated assumption failures;
- indicator value;
- Harm-Gate value;
- revision discipline.

Do not claim forecasting superiority without an appropriate benchmark.

## Anti-Hindsight Controls

Prohibited:
- grading known-outcome analysis as prospective forecasting;
- changing resolution criteria after the outcome;
- deleting misses;
- reporting only successes;
- calling a directional guess a hit when the defined event did not occur;
- extending the time window after expiry without recording timing failure;
- converting probability into certainty;
- confusing operational preparation with proof of intent;
- assigning high confidence because all four pillars agree;
- using Harm Gate consequence to inflate event probability;
- treating media volume as independent corroboration;
- using XFACTOR as an unfalsifiable catch-all.

## Harm-Gate Forecast Matrix

| Probability | Consequence | Preparation reversibility | Default posture tendency |
|---|---|---|---|
| Low | Low | High | OBSERVE |
| Low | High | High | OBSERVE / low-regret PREPARE |
| Low | High | Low | VERIFY; stronger assurance before irreversible action |

| High | High | High | VERIFY / CONTAIN planning |

## Forecast Quality Gate

Before release answer YES/NO:

1. Outcome observable and resolvable?
2. Horizon explicit?
3. Current facts separated from future inference?
4. Source lineage/independence checked?
5. Viable alternative tested?
6. Binding bottleneck identified?
7. Necessary/enabling/blocking conditions distinguished?
8. Leading indicators specified?
9. Disconfirmers specified?
10. Observability considered before using absence?
11. Probability separated from analytical confidence?
12. XFACTOR useful and falsifiable?
13. Harm Gate run?
14. Posture proportionate/reversible where possible?
15. Forecast frozen prospectively?
16. Can a future reviewer score it without asking what the analyst meant?

If 1, 2, 3, 9, 13, 15, or 16 = NO, status is:

`NOT CALIBRATION-READY`

## Runtime Integrity / Stale-State Rule

Before consequential forecasting verify:
- forecasting skill version matches intended framework package;
- current Master/Meta-Framework is loaded;
- Calibration Log is available;
- source environment is current enough for the requested horizon;
- Harm Gate and Forward-Posture doctrine are present.

If not:

`FORECASTING STATE: DEGRADED — VERSION / SOURCE / RUNTIME DRIFT`

Package presence is not proof of live runtime synchronization.

The local `vessell.evaluation` module implements a limited retrospective
evaluation of externally generated CDC ensemble incident-death forecasts:
source hashes, exact location/date joins, explicit duplicate/nonfuture/missing
exclusions, MAE, a persistence comparison, and 95% interval score/coverage.
Its synchronized output is not prospective validation of framework-generated
forecasts. See [evaluation methods](docs/evaluation-methods.md) for scope and
the evidence still needed before efficacy claims.
